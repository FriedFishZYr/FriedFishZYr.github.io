Summary

  • The system generates narrated, interactive feedback before the lesson. A reasoning model writes a structured spec for each anticipated wrong answer, one template renders it, and only small model calls run while a learner waits.
  • In a randomized study with 138 learners, layering the feedback produced more practice inside it (a median of 17 embedded submissions vs. 12) but no significant difference in post-test or transfer scores.
  • In a follow-up analysis of the layered condition, a fully correct embedded answer went with fixing the original problem: the adjusted probability of a correct next attempt was 85.2%, against 54.7% after an incorrect one. This is an association, not a causal effect.

We built a system that turns a wrong answer into narrated, interactive feedback, then tested it with 138 learners in a randomized study. This piece follows one error through that system, from the model’s input to the learner’s next attempt.

The error is small. A learner estimating the slope of f(x) = x² at x = 2 picks the difference quotient (x² − 4) / (x + 2). The numerator is right: it measures how far the height has moved from the point at x = 2. The denominator measures horizontal distance from −2 instead.

So where should the horizontal distance start?

Generation happens before the learner waits

Generating multimodal feedback is slow, and a learner who has just made a mistake shouldn’t wait for it. So we moved almost all of the generation to before the lesson (Figure 2).

Before the lesson, GPT-5.5 at high reasoning effort receives the problem statement, answer options, reference answer, a candidate response, the topic and target skill, instructional guidance, and the problem image when there is one. It returns a structured JSON spec covering the diagnosis, explanation, visual scenes, interactions, an embedded question and a narration script. A shared HTML template renders every spec the same way, and GPT-4o-mini-tts voices the script with the marin voice. Multiple-choice items get one prepared branch per answer option; short-answer and open-response items get branches for anticipated error patterns.

During an attempt, a multiple-choice selection simply retrieves its prepared branch. For short and open responses, GPT-4.1-mini classifies the learner’s answer into the closest anticipated error pattern, so the diagnosis can adapt while the prepared explanation and activities are reused. The only other live call comes after the learner answers the question inside the feedback: GPT-5.5 at low reasoning effort writes a brief reply.

The spec is a contract between model and template

Everything the learner sees and hears is specified as data. Figure 3 reconstructs one branch, the one for the x + 2 answer, in a simplified schema. The field names are illustrative, but the shape mirrors what the generator returned.

  1. Visual scene. Names the interactive graph for this error. In the study build, the generator also wrote the widget’s code, which the template mounted in the diagnosis scene.
  2. Timed cues. Each marker appears at a fraction of its narration line, so the dashed bar shows up just as the voice reaches “from −2”.
  3. Narration script. One line per scene, voiced by GPT-4o-mini-tts. The same text drives the captions, so the feedback still works with the sound off.
  4. Embedded question. Targets the exact repair, the denominator, with accepted answers for grading.
  5. Gate. Keeps the next action locked until the learner submits an answer and receives feedback. Correctness isn’t required.

Because the spec is data rather than markup, it can be inspected before any learner sees it, and a single template keeps layout, controls and captions consistent across all 20 items.

Five decisions, each traded against something simpler

Five decisions shaped the system. Each one was a trade against a simpler alternative.

  1. Generate a spec, not a page. Rather than asking the model for finished HTML per item, the model writes structured data and one template renders it. Layout, controls and captions stay consistent, and each spec stays inspectable.
  2. Prepare before the lesson. Generating after every wrong answer would put the slowest call on the learner’s path. Multiple-choice options are a closed set, so every branch can exist in advance.
  3. Classify free responses, then reuse. Instead of writing fresh feedback for each short or open response, a small model picks the closest anticipated error. The diagnosis adapts to the learner’s answer, and the prepared explanations and activities are reused.
  4. Spend reasoning where nobody is waiting. Generation runs at high reasoning effort before the lesson. The live reply to an embedded answer runs at low effort, because the learner is waiting and the reply only needs to be brief.
  5. Hold content constant across conditions. Both study conditions use the same materials. Only the timing of sections differs, so content differences can’t explain the results.

The learner meets one error three ways

The feedback works on the same mistake through three channels. The learner drags x along the curve and watches both distances update (Figure 4). A voiced script walks through the graph while timed cues reveal each bar, and captions, playback speed, play/pause and section navigation let the learner set the pace. The feedback then ends with a question that keeps x² − 4 and asks for the denominator.

Layering changes timing, not content

The study compared two ways of timing the same materials (Figure 5). Non-layered feedback shows all four sections in every episode: the visual diagnosis, a concept explanation with a new worked example, the embedded question, and an explanation of the correct original answer, which opens once the embedded answer is submitted. Layered feedback starts with only the diagnosis and the embedded question, then sends the learner back to revise the original answer.

On a layered multiple-choice item, a wrong retry repeats the diagnosis-plus-question cycle until the learner chooses correctly. On short- and open-response items, full four-section feedback opens from the third original attempt if the answer is still wrong; the featured example is multiple choice, so it never reaches that rule. In both conditions, correct answers get a brief confirmation.

More practice inside feedback did not raise test scores

138 U.S. college students with at most one prior calculus course were randomly assigned to layered (64) or non-layered (74) feedback. Each completed a six-item pre-test and a baseline survey, about 45 minutes of learning by doing, a six-item post-test with two transfer items, and a post-survey (Figure 6). The lesson covered five derivative topics in 29 items: 20 with generated feedback (15 multiple choice, 3 short answer, 2 open response) and 9 worked examples.

Layered learners answered more often inside the feedback, a median of 17 embedded submissions compared with 12 for non-layered learners (p < .001). That extra practice did not show up in test scores. After adjusting for pre-test, the groups did not differ significantly on the post-test (p = .211) or the transfer test (p = .551), though both groups improved from pre-test to post-test. Accuracy inside the feedback ran the other way: 41% of layered learners’ embedded answers were fully correct, compared with 50% for non-layered learners (medians, p = .035).

A correct embedded answer went with fixing the original problem

Counting responses inside the feedback says little about whether they helped. So a follow-up analysis asked a narrower question: after answering the embedded question, did learners fix the original problem? It uses only the layered condition, and its denominator is separate from the randomized study.

Each episode starts at a learner’s first incorrect attempt on a problem, takes the last recorded embedded score for that attempt, and pairs it with the next attempt on the same problem (Figure 8). There were 492 episodes with known scores across 63 learners. 361 of them, from 56 learners, had a scored retry. The other 131 had no observed retry; they stay in their own category rather than being counted as wrong.

We estimated the difference with a Bayesian logistic regression that includes crossed learner and problem intercepts and adjusts for pre-test. Among observed retries, the adjusted probability of correcting the original problem rose from 54.7% after an incorrect embedded answer to 85.2% after a fully correct one: a difference of 30.5 percentage points (95% Bayesian credible interval, 18.7–43.0). This is an association. It does not show that the embedded question caused the correction.

Limitations

Several limits shape how far these results can be pushed.

  • The worked example has not been checked against the deployed build. It comes from the August design archive, and its match to the study build is unverified.
  • No latency was measured. Reducing wait time was a design goal, but the manuscript reports no latency measurements.
  • The embedded scores are automated. The system scored embedded answers as incorrect, partial or correct, and those scores have not been validated against human ratings.
  • The next-attempt result is an association. It covers observed retries in one condition and does not show that the embedded question caused the correction.
  • The interaction shown here is a reconstruction. The graphs, schema and walkthrough on this page are original illustrations with scripted responses. They contain no participant data and no study assets.

Conclusion

The central design choice was to put generation where nobody is waiting. A reasoning model writes structured specs ahead of time, one template turns them into narrated, interactive feedback, and only small, fast calls run during the lesson. Each learner met one error through a graph, a voice and a question, all aimed at the same repair.

The results are more modest than the system. Layering produced more practice inside the feedback but not better test scores. Answering the embedded question correctly went with fixing the original problem, which makes the embedded score a candidate signal for deciding when to offer more support.

The next step is to verify which prompt and score version each embedded answer belongs to, then read a small set of cases where a fully correct embedded answer was followed by an incorrect retry. That would show whether the original error persisted or a different mistake appeared.
